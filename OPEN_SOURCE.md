# Open Source at Memi

Memi is developed in public around a small number of supported product surfaces. We value useful issues, reproducible evidence, focused pull requests, and respectful technical disagreement.

## Ways to participate

1. Use the first-audit command and report unclear output or missing evidence.
2. Improve a focused skill, fixture, example, or documentation path.
3. Reproduce a design-engineering problem in `design-sandbox`.
4. Propose a cross-repository change in `memi` Discussions before implementing it.
5. Help review accessibility, platform compatibility, provenance, and licensing.

Issues labeled `good first issue` are scoped for a first contribution. Issues labeled `help wanted` have maintainer agreement but need an owner.

## Collaboration model

- Work happens in issues, Discussions, and pull requests so decisions remain searchable.
- Contributors do not need advance permission to take an unassigned `good first issue`.
- Maintainers will identify ownership conflicts early and prefer the smallest independently useful change.
- Pull requests should stay reviewable, preserve attribution, and include the evidence needed to reproduce the result.
- Recognition is based on substantive contribution, not promotional activity or manufactured engagement.

## Repository lifecycle

Only supported products, distribution surfaces, and reproducible proofs belong in the organization. Incubating work is labeled clearly; abandoned or superseded work is archived with a replacement or end-of-life note. The current classification is documented in [ORG_ARCHITECTURE.md](ORG_ARCHITECTURE.md).
